Проанализировать **Q02/Q03/Q06/Q07/Q08**: возможная *стационарная* модель прямотока/противотока с энергобалансом, границами, переносом теплоты, зависимостью свойств, моделью датчиков и применимостью корреляций; отдельно решить вопрос о необходимости переходной динамики. Сопоставить 1–2 минимально достаточных варианта, указав входы, неизвестные и вычислительную устойчивость, не выбирая вариант без обоснований.

Проверить корреляции для трубы и кольца, LMTD, единицы и знаки потоков; выделить спорные места методички. Подготовить независимые численные эталоны и тестовые режимы, которые *могут* проверить правильную модель.

## Этап В0 — межлабораторная архитектура и сравнительный аудит (выполнен, без кода)

**Статус:** завершён сравнительный аудит всех восьми направлений с обращением к локальным методическим указаниям и протоколам. Результаты: [laboratory-portfolio.md](design/laboratory-portfolio.md) и [application-architecture.md](design/application-architecture.md). Обновлены Q17/Q18 в [OPEN-QUESTIONS.md](OPEN-QUESTIONS.md).

**Главный вывод:** общий API должен допускать качественную схему без чисел, диаграмму без приборов и насосов, опыт по введённым измерениям и физическую симуляцию. Общими остаются идентификаторы модулей, команды/ответы, сведения о происхождении, справка, диагностики, сеанс и сохранение; обязательной общей модели оборудования нет.

**Кандидат для второй архитектурной проверки:** влажный воздух (i–d-диаграмма). Прежде чем отображать вычисленные точки/процессы как физически точные, нужны психрометрическая постановка, давление, область применимости и независимые эталоны. Различать две установки выпаривания: локальный трёхкорпусный протокол и двухкорпусную методику. Никакие новые физические модели не утверждены.

**Не закрыто:** Q17 — контракт пока проверен лишь документально; Q18 — очерёдность и научная постановка второго модуля ещё не согласованы. Нет разрешения начинать код только на основании завершения В0.

## Этап Д0 — минимальный контракт общих API для неоднородных модулей (выполнен, без кода)

**Статус:** подготовлен [проект контракта](design/application-api-contract.md), включая два бумажных примера, M01–M10 и границы первого кодового среза. Контракт не утверждён, тесты и реализация не выполнялись; Q17 остаётся открытым.

Выполненная постановка: на основе [архитектуры](design/application-architecture.md), [сопоставления модулей](design/laboratory-portfolio.md) и [методики](design/methodical-interaction.md) подготовить **только проект** минимального headless Python API и JSON CLI. Рассмотреть два **разных** сценария:

1. **Теплообменник:** учебный ε–NTU пример с известными C/UA и тестовым эталоном, отдельный отказ выдачи виртуального показания конкретного стенда без утверждённой модели.
2. **Влажный воздух:** качественный выбор точки/области и сохранение черновика **без** неподтверждённых численных свойств и физического построения.

Предусмотреть стабильные ID модулей/действий/материалов, версии сеанса, типизированные входы с единицами при необходимости, статус происхождения (не путать с проверкой), диагностические коды, варианты результата (качественный выбор, число, точка, серия), ссылки на материалы, сохранение и восстановление. Не навязывать общему контракту насос, таймер, расчёт, фиксированную последовательность или обязательную оценку.

**Выход:** `docs/design/application-api-contract.md` — таблица операций и инвариантов, JSON-примеры запросов/ответов двух модулей, сопоставление с M01–M10 и Q17, явные решения/альтернативы и границы первого кода. При необходимости точечно уточнить архитектуру, Q17 и план. Не создавать Python-пакет, JSON schema, GUI, зависимости, заглушки или тесты в этом задании.

**Цель перехода:** после анализа и утверждения минимального контракта отдельно разрешить узкий кодовый spike либо первый headless-модуль. Наличие проектного API не снимает научные блокеры G2.
