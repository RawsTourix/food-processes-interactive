# Codex — план делегирования

**Статус:** DRAFT. Работать итерациями; до завершения аудита не разрабатывать физическую модель или финальный UI.

## Задание 0 — исследование, без записи кода

**Вход:** методические документы из архива пользователя, скриншоты и, после передачи, оригинальный Flash EXE. Бинарный файл и сторонние материалы НЕ следует автоматически публиковать в открытом репозитории.

**Часть А. Инвентаризация:** каталог документов, их назначение и полнота, перечень предполагаемых лабораторных, совпадение с экзаменационными темами. Для каждого факта — документ и страница/объект.

**Часть Б. Теплообменник:** восстановить проверяемую последовательность работы; органы управления и состояния; таблицы; формулы; величины и единицы; происхождение виртуальных показаний; справочные материалы; диагностические сообщения. Составить карту «ввод → действие → показание → вычисление → запись в протокол».

**Часть В. Оригинальный EXE:** первоначально только статический осмотр — формат PE, встроенный SWF/ресурсы и метаданные, возможность декомпиляции Flash-проектора. НЕ запускать неизвестный EXE на рабочей системе; динамическое обследование только в изолированной Windows-среде без сети и с явной фиксацией наблюдений. Не считать восстановленный ActionScript корректной научной моделью без проверки. Оригинальные ресурсы не коммитить в публичный репозиторий.

**Часть Г. Риски:** ошибки и неоднозначности в первоисточниках, недостающая геометрия, границы применимости расчётов, возможное расхождение оригинала и методики, лицензирование.

**Выход:** индекс источников, сценарии опытов, реестр формул, карта данных/состояний, матрица прослеживаемости, список неизвестного. Только документированный отчёт/PR; никакого автоперехода к реализации.

## Задание 1 — технический spike упаковки

Минимальное окно pywebview с SVG, кнопкой, одним Python API-вызовом, сохранением тестовых данных и тестом жизненного цикла. Проверить локально на Windows, измерить реальный размер одного EXE, время запуска, потребление памяти, требования к WebView2. Не писать научную модель ради spike. Зафиксировать команды сборки и результаты замеров.

## Задание 2 — API-контракт и тесты

На основе аудита согласовать команды, типы входа/выхода, диагностику, сохранения и эталоны. Реализовать Python-модель предметных сущностей, headless CLI и pytest. Полный воспроизводимый сценарий должен проходить без UI. GUI ещё не разрабатывается.

## Задание 3 — первая лабораторная

Реализовать только проверенные расчёты и состояния теплообменника; научно не подтверждённые элементы явно пометить или отложить. Покрыть валидными/невалидными кейсами и независимыми численными проверками.

## Задание 4 — интерфейс и материалы

Нарисовать интерактивную SVG-схему, связать элементы с Python API через pywebview, добавить единый справочник/материалы, протокол, подсказки, автосохранение и краткие экзаменационные памятки. Проверить, что GUI не создаёт собственный источник состояния или вычислений.

## Задание 5 — упаковка и расширение

Собрать Windows EXE, провести smoke-тест на чистой Windows, отладить сохранения и обновления. Только после завершения первой лабораторной выбрать вторую по готовности источников. Не строить абстрактную «платформу» заранее.

## Требования к каждому результату Codex

Указать: что прочитано, что установлено из источника, какие предположения сделаны, что не доказано; изменённые файлы; команды тестов и фактические результаты; оставшиеся риски. Проводить работу отдельными малыми PR. Не заменять первоисточник предположениями модели.
