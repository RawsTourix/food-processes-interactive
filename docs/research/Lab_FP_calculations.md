# Lab_FP: расчёты, данные и проверки

Связанные документы: [основной анализ](Lab_FP_analysis.md), [рабочий процесс](Lab_FP_workflow.md), [план динамического исследования](Lab_FP_dynamic_test_plan.md). Подтверждение: экспорт FFDec 26.4.0 `scripts/frame_1/DoAction.as` и `DoAction.pcode` из `main.swf` с хешем из основного анализа; обозначения `Formula_*` — идентификаторы экземпляров. Поля `E1…` и `S1…` означают `Enterfield_1…` и `Showfield_1…`. Физический смысл полей определён по положению в экспортированных спрайтах; их подписи и контекст могут быть неоднозначными. Ввод чисел в спрайте означает текстовое поле, а не строго типизированный параметр.

`R_n(x)=Math.round(x·10^n)/10^n`. Различать округлённый вывод окна и ввод в другое окно: это не автоматическая цепочка. В качестве методического источника далее используется местный `Методичка (2).pdf`, страницы PDF. Условия применимости методики приведены как её утверждения, а не как независимая научная валидация.

## Связи окон и данных

`Formula_1_j.Save` сохраняет `F_1_j_E1`, `F_1_j_S1`; результаты отражаются в таблице `Rez_1_j`. `Formula_2_j.Save` сохраняет скорость `F_2_j_S1`, которую затем читает `Formula_6_j.Showfield_3`. Скорость в окне Re пользователь вводит отдельно: автоматической передачи `F_2_j_S1 → Formula_3_j_1.E1` в исследованном главном блоке нет.

Вложенные `Formula_3_j_1…4.Save` присваивают `F_3_j_k_S1` и одновременно переносят результат в `Formula_3_j.Showfield_k`; последнее служит входом трёх кнопок Nu. `Formula_3_j.Save` сохраняет `S5` как `F_3_j_S5` для сводной таблицы, но E1–E3 надо заполнить отдельно. Для вычисления сопротивления кнопки читают сохранённый `F_3_j_1_S1`, не текущий текст окна Re. `Formula_5_j.Save` сохраняет `S3` как `F_5_j_S3`, которое читает `Formula_7_j.S2`. Итоговые `Rez_*` читают соответствующие сохранённые `F_*_S*` каждый кадр (AS 1330–1397). Значения между вычислением и `Save` могут отличаться от сводки. `Load` возвращает сохранённые строки, но последующий `onEnterFrame` может пересчитать выход.

## Подтверждённые ошибки и спорные места

1. Логарифмический напор: оригинал использует `(A+B)/ln(A/B)` в обоих `Formula_5_j.RE_2`, P-code строки 21645–21820; методика стр. 14, формула 36, требует `(Δtб−Δtм)/ln(Δtб/Δtм)`. Ещё нужно доказать соответствие A и B концам аппарата для каждого направления. Для равных положительных напоров правильный предел равен общей разности; оригинал не обрабатывает случай. Предполагаемое исправление — корректные концевые разности, числитель с разностью, проверка области и предельный случай.
2. `Formula_3_4_2` читает `Formula_3_1_2.E1…3` вместо собственных входов (AS 2382–2404, P-code 34722–34836). Предполагаемое исправление — собственные поля после проверки ожидаемого сценария.
3. `Formula_6_j` отображает значение под заголовком кПа без деления на 1000 при вводе L, d, ρ, V в СИ. Для этих единиц выражение размерно даёт Па. Предполагаемое исправление — явная конвертация или правильная единица; также проверить скрытые подписи и фактический формат.
4. Ротаметр воды: кадр 28 на глубине цифрового значения размещает текстовый ресурс 249 `л/мин` вместо 289 `1.04`, XML `DefineSprite_368`; эффект наложения и реальное изображение проверить динамически. См. [рабочий процесс](Lab_FP_workflow.md).
5. В `Hide_Window` три отображаемых базовых значения не совпадают с коэффициентами расчёта, а для отдельных ветвей остановки потоков знак выглядит несогласованным — подробнее основной анализ §10.6. Происхождение коэффициентов не обнаружено: наличие регулирующих полей не доказывает ни измеренной калибровки, ни физической модели.

## Выполненные численные проверки

27.10.2026 в отдельном `node`-процессе выполнены арифметические выражения, исходники `numerical-check.js`, `numerical-refined.js` находятся во временном каталоге аудита. Опорные значения расхода, Re, Pr, K, q2, давления и логарифмического напора независимо пересчитаны в Python с `decimal` с точностью 35 знаков командой `python independent_reference.py` во временном каталоге: например, K=303,31078675685 и напор=28,85390081778. Это не AVM1-плеер; результаты IEEE/JavaScript и приведённые данные не представляют наблюдение оригинала. Примеры иллюстрируют арифметику, а не калибровку установки.

Граничный отдельный прогон Node.js дал: `1/0 → Infinity`, `0/0 → NaN`, оригинальный логарифмический напор при A=B=30 → `Infinity`, при A=20, B=−5 → `NaN`, при B=0 и A=20 → 0; `''*2/'' → NaN`, `(-1)**0.2 → NaN`. Это проверка именно JavaScript-подстановки: перенос на AVM1-преобразование пустых/отрицательных полей и фактическое отображение Flash следует подтвердить в VM. Ввод отрицательного значения может ограничиваться `restrict`, но вставка, программные присваивания и точное поведение ввода не проверены. При равных положительных напорах методический предел равен 30 К; для нулевого или отрицательного напора требуется отдельная предметная диагностика.

Для воспроизведения основных чисел в Node.js (оператор `**` применяется только в отдельной проверке, не в коде Flash):

```javascript
const R = (n,x) => Math.round(x*10**n)/10**n;
const F=R(7,2*0.00001667), S=Math.PI*(0.029**2-0.025**2)/4;
const V=R(6,F/S), Re=R(5,V*0.004/1e-6), Pr=R(5,4180*0.001/0.6);
console.log({F,S,V,Re,Pr,Nu:R(5,0.7*(Re*Pr)**0.2*(100000*Pr)**0.1)});
console.log({original:R(5,(40+20)/Math.log(40/20)),method:(40-20)/Math.log(40/20)});
console.log({pressure:R(6,(0.032*4/0.021+1.5)*1000/2)});
```
