# Открытые решения и неопределённости — Food Processes Interactive

**Редакция:** 0.1, 27.10.2026. **Статус:** живой реестр; не подменять отсутствие доказательств личными догадками.  
**ТЗ:** [SPEC-DRAFT.md](SPEC-DRAFT.md). **Основания:** [реестр вычислений оригинала](research/Lab_FP_calculations.md), [методический аудит](research/Lab_FP_methodical_audit.md).

## Как вести реестр

- **Принято:** решение владельца проекта или проверенный первоисточник зафиксирован с основанием.
- **Открыто:** данных недостаточно; приведена минимальная следующая проверка.
- **Отложено:** не блокирует ближайший проверяемый результат.
- **Блокер G2:** без ответа запрещено предъявлять виртуальные показания как научно обоснованный эксперимент. Блокер G2 не мешает проектированию схемы, справочника, ядра состояний и CLI.
- **Специфическое утверждение из Flash или методички** — ещё не независимый физический эталон.

Источники первичной методики и оригинальный EXE остаются локальными. Публикация реестра не означает публикации исходных материалов.

## Приоритет закрытия вопросов

**Следующие самостоятельные исследовательские задания (без программирования приложения):**

1. **Научный аудит Q01 + Q04 + Q05:** из методички и независимых источников получить геометрию и диапазоны, определить допустимый набор физических параметров. Выход: таблица параметров с происхождением, единицами и статусом, без выдуманных значений.
2. **Выбор модели Q02 + Q06 + Q07 + Q08:** сопоставить варианты стационарной модели, условия применения корреляций и независимые эталоны. Выход: короткая спецификация расчётного ядра с доказательствами/альтернативами и отдельным списком неподтверждённого.
3. **Методический выбор Q09 + Q10:** определить самостоятельные действия студента и допустимость внешних эталонных данных. Выход: согласованный список расчётных заданий и правил проверки.
4. **Технический spike Q13:** независим от научного аудита; может выполняться отдельно после разрешения начать код прототипа.
5. **Решения по контенту Q11/Q12, сохранению Q15/Q16; UX VM Q14** — по мере развития, без блокировки первых трёх пунктов.

## Формат записи решения

Для каждой закрываемой строки добавлять: **решение, кто согласовал, дата, проверяемое основание (локальный документ + страница / формула / результат теста), ограничения и последствия для ТЗ**. Устное предположение или совпадение с Flash не меняет статус на «принято».

**Следующий предлагаемый шаг:** Q01/Q04/Q05 — доказательная спецификация оборудования и свойств, затем варианты Q02. Не начинать реализацию научной модели только по найденным константам оригинала.
