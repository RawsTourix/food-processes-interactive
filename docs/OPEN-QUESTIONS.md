# Открытые решения и неопределённости — Food Processes Interactive

**Редакция:** 0.1, 27.10.2026. **Статус:** живой реестр; не подменять отсутствие доказательств личными догадками.  
**ТЗ:** [SPEC-DRAFT.md](SPEC-DRAFT.md). **Основания:** [реестр вычислений оригинала](research/Lab_FP_calculations.md), [методический аудит](research/Lab_FP_methodical_audit.md).

## Как вести реестр

- **Принято:** решение владельца проекта или проверенный первоисточник зафиксирован с основанием.
- **Открыто:** данных недостаточно; приведена минимальная следующая проверка.
- **Отложено:** не блокирует ближайший проверяемый результат.
- **Блокер G2:** без ответа запрещено предъявлять виртуальные показания как научно обоснованный эксперимент. Блокер G2 не мешает проектированию схемы, справочника, ядра состояний и CLI.
- **Специфическое утверждение из Flash или методички** — ещё не независимый физический эталон.

Источники первичной методики и оригинальный EXE остаются локальными. Публикация реестра не означает публикации исходных материалов.

## Принятые решения (не переоткрывать без новой причины)

| ID | Решение | Основание / эффект |
|---|---|---|
| D01 | Python как предметное ядро; GUI — pywebview + HTML/CSS/SVG как предварительный стек | Пользователь согласовал Python и pywebview; упаковку подтвердить spike |
| D02 | API-first/headless-first, воспроизводимые сценарии через Python + JSON CLI | Codex должен тестировать полный процесс без окна |
| D03 | Одно офлайн-приложение Windows, желательно одним EXE; без веб-аккаунтов и внешнего бэкенда | Формат и реальные зависимости подлежат измерению |
| D04 | Основные разделы: лабораторные, единый справочник, методические материалы, краткие экзаменационные памятки и сохранения | Без отдельной LMS и генератора билетов |
| D05 | Первый объект разработки — теплообменник; первыми исследуются прямоток и противоток | Остальные лабораторные после научной и методической проверки |
| D06 | Оригинальный EXE и PDFs хранятся локально; код, собственная документация и допустимые производные выводы — в публичном GitHub | Не коммитить сторонние бинарники и сканы |
| D07 | Методическая самостоятельность: управление, фиксация опыта, выбор метода, вычисление и вывод за студентом; контекстная помощь и понятная диагностика — у программы | [Предварительный учебный сценарий](design/heat-exchanger-learning-flow.md) |
| D08 | Не воспроизводить эмпирические показания Flash как физически достоверную модель | Температуры привязаны к кадрам ротаметров и не имеют подтверждённой физической основы |
| D09 | Внутренние \`Save\`/\`Load\` Flash не являются стандартом новой системы сохранения | Нужны реальные пользовательские сеансы и неизменяемые снимки |
| D10 | Не требовать полноценной динамической модели, если обоснована и методически достаточна стационарная | Переходные процессы — отдельный вопрос Q03, не фиктивная анимация |

## Открытые вопросы

### A. Научная и методическая достоверность (критические для G2)

| ID / приоритет | Неопределённость | Что конкретно нужно проверить или решить | Блокирует |
|---|---|---|---|
| **Q01 / критично** | **Реальная геометрия аппарата и поверхностей.** В SWF/методике показаны размеры 21/25/29 мм, длина 1 м, четыре секции; неизвестно, к какой поверхности и гидравлическому диаметру относить коэффициенты. | Сверить схему, обозначения, внутренние/наружные диаметры, число проходов, активную длину, область теплопередачи и площадь с первоисточником; оформить утверждённую схему параметров с единицами и источниками страниц. | Модель, Re/Nu, K, Δp, эталоны |
| **Q02 / критично** | **Модель виртуальных температур.** Flash использует эмпирические коэффициенты и номера кадров вместо проверенного баланса. | Выбрать применимую стационарную постановку (энергобаланс и теплообмен прямоток/противоток), указать граничные условия, потери/допущения, свойства, численный метод и независимые решения хотя бы для нескольких режимов. Согласовать с методическими целями. | Получение показаний и сравнение режимов |
| **Q03 / отложено условно** | **Нужна ли физическая динамика и критерий «установилось»?** Старое ожидание 20–30 с связано с кадрами. | Установить, требует ли преподаватель моделировать нестационарность. Если нет — явно показывать расчёт установившегося состояния без искусственного времени прогрева; анимация отдельно. Если да — потребуются теплоёмкости/массы, начальные условия и эталоны. | Только динамический режим; НЕ блокирует стационарный G2 |
| **Q04 / критично** | **Теплофизические свойства воды и молока.** Таблицы Flash, средние температуры, состав молока и интерполяция не обоснованы для всех диапазонов. | Определить разрешённые состав/температуры/давление и источник \`ρ, c_p, μ, ν, λ, β\`; выбрать правило интерполяции/экстраполяции, проверить единицы и диапазоны. | Баланс, Re/Pr/Gr/Nu, Δp |
| **Q05 / высоко** | **Рабочие диапазоны и правила эксплуатации.** Ротаметры отображают 0,50–2,50 л/мин, настройки температур Flash 10–90 / 10–40 °C, но фактическая область применения не доказана. | Разделить диапазон UI оригинала, утверждённый диапазон физической модели и учебные рекомендации. По выбранной модели проверить поведение на границах; не назначать численные запреты произвольно. | Проверка ввода, устойчивость модели |
| **Q06 / критично** | **Корреляции Nu и границы Re/геометрия.** В методике есть три зависимости и спорные области; видна опечатка \`23320<Re<4500\`. | Проверить первоисточник/независимую учебную литературу: область ламинарного, переходного, турбулентного течения; соответствие вертикальной трубе и кольцевому каналу, граничные значения и выбор корреляции. Отдельно определить, какие решения должен выбирать студент. | Проверка Nu, α, зависимостей и оценки |
| **Q07 / высоко** | **Сопротивления, стенка и падение давления.** Плоская стенка в коде, цилиндрическая геометрия установки; Δp рассчитано в Па при подписи кПа. | Определить поверхность нормировки коэффициента K, сопротивление стенки/загрязнений, коэффициенты трения и местных потерь, источники параметров, знаки и конвертацию Па/кПа. | Проверенная теплопередача и Δp |
| **Q08 / критично** | **Температурный напор, знак потоков, «КПД».** Подтверждены ошибка \`(A+B)/ln(A/B)\`, спорное соответствие концов и знаки \`q_1\`/\`q_2\`. | Зафиксировать положительные направления тепловых потоков; корректные концевые разности для обоих режимов и предел при равных напорах; дать смысл «КПД» либо заменить показатель на физически определённый; получить независимые численные эталоны. | Энергобаланс, оценка результатов, сравнение |
| **Q09 / высоко** | **Какие расчёты студент обязан делать сам и что считается правильным?** Flash допускает ручной выбор нескольких формул и \`Save\` результатов. | Согласовать с преподавателем минимум расчётов, самостоятельность, последовательность, допустимые округления, относительные/абсолютные допуски, право видеть подробное решение и требования к выводу. Оформить таблицу «шаг → выбор студента → проверка». | Методическая приёмка G3, автооценка ответов |
| **Q10 / высоко** | **Допустимы ли утверждённые исходные наборы данных вместо симуляции?** | Если Q02 не закрыт, согласовать явный учебный режим с достоверно атрибутированными наборами (печатная методика/измерения) для тренировки расчётов. Обязательно показывать «исходные учебные данные», а не «измерение виртуального стенда». | Полноценный учебный сценарий до готовности модели |

## Приоритет закрытия вопросов

**Следующие самостоятельные исследовательские задания (без программирования приложения):**

1. **Научный аудит Q01 + Q04 + Q05:** из методички и независимых источников получить геометрию и диапазоны, определить допустимый набор физических параметров. Выход: таблица параметров с происхождением, единицами и статусом, без выдуманных значений.
2. **Выбор модели Q02 + Q06 + Q07 + Q08:** сопоставить варианты стационарной модели, условия применения корреляций и независимые эталоны. Выход: короткая спецификация расчётного ядра с доказательствами/альтернативами и отдельным списком неподтверждённого.
3. **Методический выбор Q09 + Q10:** определить самостоятельные действия студента и допустимость внешних эталонных данных. Выход: согласованный список расчётных заданий и правил проверки.
4. **Технический spike Q13:** независим от научного аудита; может выполняться отдельно после разрешения начать код прототипа.
5. **Решения по контенту Q11/Q12, сохранению Q15/Q16; UX VM Q14** — по мере развития, без блокировки первых трёх пунктов.

## Формат записи решения

Для каждой закрываемой строки добавлять: **решение, кто согласовал, дата, проверяемое основание (локальный документ + страница / формула / результат теста), ограничения и последствия для ТЗ**. Устное предположение или совпадение с Flash не меняет статус на «принято».

**Следующий предлагаемый шаг:** Q01/Q04/Q05 — доказательная спецификация оборудования и свойств, затем варианты Q02. Не начинать реализацию научной модели только по найденным константам оригинала.
