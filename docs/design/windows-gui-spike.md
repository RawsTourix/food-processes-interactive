# Windows GUI spike: pywebview, мост и упаковка

**Дата:** 29.10.2026. **Статус:** технический прототип реализован, автоматические проверки и две сборки выполнены; ручной визуальный smoke-test и чистая Windows не проверены. Этап Г не считать полностью принятым до ручной проверки. Это не лабораторная и не подтверждённая физическая модель.

## Состав и поток данных

`spike_gui.py` — отдельный вход и `Bridge.request`, единственный делегат в `Application.request`. Один `threading.Lock` сериализует вызовы мостом, поскольку [pywebview выполняет API-методы в отдельных потоках](https://pywebview.flowrl.com/guide/interdomain). Клиент в `spike.html` ожидает `pywebviewready`, асинхронно отправляет структурированные запросы и показывает ответ или ошибку; пока операция выполняется, элементы блокируются. HTML/CSS и SVG встроены в один локальный файл; локальные системные шрифты, без внешних URL и CDN. Схемы условные; R04 явно подписан как учебная фикстура. Психрометрические значения и приборные показания отсутствуют.

Два сеанса имеют отдельные UUID и ревизии. Сохранение выполняется `session.save` → `storage.write` с токеном поколения; повторная запись использует новый токен, конфликт не разрешается автоматически. Восстановление — `storage.read` → `session.restore`. Существующий сеанс с тем же ID не перезаписывается. Обычное приложение использует стандартный пользовательский каталог ядра `%LOCALAPPDATA%/FoodProcessesInteractive/sessions`, не папку EXE и не временную распаковку. Для инструментальной проверки каталог тестовых данных изолирован во временном каталоге. Ответы и фикстуры в JS не вычисляются.

Ресурс находится относительно `__file__`, без изменения рабочего каталога. Python читает `spike.html`, затем передаёт содержимое в `webview.create_window(html=...)`; внешние CSS/JS-файлы приложению не требуются. Тестовый `spike_probe.js` подключается только при `--probe`. В отличие от относительного пути к файлу, для которого pywebview может запустить сервер от каталога точки входа, встроенный HTML не требует этого механизма ([документация pywebview](https://pywebview.flowrl.com/guide/usage.html)). Реальный `--probe` сообщил `location.protocol == "about:"`; `netstat -ano -p tcp` во время источникового запуска не показал TCP-сокетов у двух процессов Python. Все процессы WebView2 отдельно на сеть не исследованы; отключение интернета не проводилось.

## Зависимости и среда

Фактически установлены в локальной `.venv`: Python 3.11.9 x64, pywebview 6.2.1, pythonnet 3.2.1, PyInstaller 6.22.3, pytest 9.2.0; pywebview также установил `bottle`, `proxy_tools`, `typing_extensions`, а pythonnet — `clr_loader` и зависимости. Windows сообщила build 10.0.26200; .NET Framework 4.8.09221 (Release 533509); в реестре найден WebView2 Runtime 156.0.4314.50. Версии воспроизводимого верхнего уровня перечислены в `requirements-spike.txt`.

По [документации pywebview](https://pywebview.flowrl.com/guide/web_engine.html) Edge Chromium требует .NET Framework и WebView2 Runtime; иначе возможен устаревший MSHTML. Прототип до загрузки GUI проверяет зарегистрированный Evergreen Runtime и .NET Framework 4.6.2+, затем запрашивает `gui="edgechromium"`; при отсутствии найденных требований показывает ошибку и завершает запуск. Отсутствие Runtime проверено только тестом с подменой реестра, не на реальной чистой машине. В фактических запусках подтверждён `edgechromium`. По [Microsoft](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution) Runtime следует отдельно учитывать при доставке; перечень систем WebView2 приведён [в документации Microsoft](https://learn.microsoft.com/en-us/microsoft-edge/webview2), но совместимость **всего** приложения с каждым вариантом не проверялась.

PyInstaller включает интерпретатор Python в пакет ([документация](https://pyinstaller.org/en/stable/operating-mode.html)), однако отдельной Windows без установленного Python и WebView2 для проверки нет. Не утверждается полная автономность от системного WebView2/.NET или успешность запуска на неподготовленной машине. Один EXE — предмет дальнейшей проверки, а не готовый релиз.

## Фактические испытания Windows

1. Запуск из исходников в песочнице: pywebview сообщил ошибку инициализации WebView2 `0x8000FFFF (E_UNEXPECTED)`. Вне песочницы при инструментальном запуске событие загрузки вернуло `renderer=edgechromium` через 1,859 с; далее реальный JS→pywebview→Python мост вернул успешные проверки условного теплообменника, качественной точки, справки, отказов неподтверждённых свойств и тестовой записи/чтения. `platform=edgechromium`, ошибок скрипта не сообщено.
2. Настоящие `onedir` и `onefile` запущены по два раза в инструментальном `--probe`: в каждом запуске WebView2 выполнил запросы обоих модулей, тестовую запись/чтение и проверку DOM, кириллицы, SVG `viewBox` и встроенного HTML. Повторный запуск каждой сборки восстановил точку из **того же изолированного тестового каталога** и сохранил её с токеном поколения. При каждом запуске получен код завершения 0 после программного закрытия окна. У onefile успешная загрузка доказывает доступ к вложенным HTML и диагностическому скрипту после распаковки.
3. На этой среде инструмент управления не предоставляет нативные окна; ручной визуальный осмотр, нажатия реальными мышью/клавиатурой, масштабирование и закрытие пользователем **не выполнялись**. Снимков окна нет. DOM-проверка с подменой элементов и реальным Python API проверяет обработчики SVG, состояние, справку, конфликт записи и восстановление, но не является проверкой рендерера или ручным smoke-test.

## Сборка и измерения

В PowerShell из корня, после установки `requirements-spike.txt`:

```powershell
.\.venv\Scripts\python -m PyInstaller --noconfirm --onedir --windowed --name FPI-Spike-Dir --distpath dist/gui-spike-dir --workpath build/gui-spike-dir --specpath . --add-data 'spike.html;.' --add-data 'spike_probe.js;.' spike_gui.py
.\.venv\Scripts\python -m PyInstaller --noconfirm --onefile --windowed --name FPI-Spike-One --distpath dist/gui-spike-one --workpath build/gui-spike-one --specpath . --add-data 'spike.html;.' --add-data 'spike_probe.js;.' spike_gui.py
```

| Вариант | Измеренный размер | Первый / повторный запуск до отчёта `--probe` | Результат |
|---|---:|---:|---|
| `onedir` | 26 258 561 байт (25,04 МиБ), весь каталог | 3,092 / 1,265 с | `edgechromium`; проверки и восстановление пройдены |
| `onefile` | 13 733 229 байт (13,10 МиБ), EXE | 1,550 / 2,024 с | `edgechromium`; проверки и восстановление пройдены |

Время — от запуска процесса до окончания автоматического обмена, не точное время первого кадра; всего по одному первому и повторному замеру, состояние системного кэша не контролировалось. Выводов о стабильной разнице скорости делать нельзя. EXE собраны `--windowed`; PE Subsystem = 2 (`WINDOWS_GUI`) у обоих, но отсутствие консольного окна визуально не проверено. Первая попытка сборки с `--specpath build/gui-spike-spec` не нашла относительные ресурсы; выше указан исправленный вызов с `--specpath .`. PyInstaller также вывел предупреждения об отсутствующих `pycparser.lextab`/`yacctab`; инструментальные запуски прошли, причина и влияние за пределами протестированных путей не установлены. `build/`, `dist/`, EXE и локальные источники в Git не добавляются.

## Автоматические тесты и оставшиеся решения

`.venv/Scripts/python -m pytest -q`: **59 passed, 1 skipped**. Пропущен прежний тест символической ссылки из-за прав Windows. Новые тесты проверяют эквивалентность bridge/API, параллельные команды с одной ревизией (успех и конфликт), обработку исключения без утечки деталей, локальность HTML, сохранение токена, отдельные сеансы, отрисовочное состояние в DOM-тесте и восстановление. Официальный рендерер тестами-подменами не подтверждается. Инструментальный реальный `--probe` выше выполняется отдельно.

Рекомендация: стек pywebview + Edge WebView2 пригоден для дальнейшего ограниченного исследования — настоящий bridge и обе упаковки работают на текущем компьютере. До выбора его для релиза нужны ручная проверка интерактивных элементов, размеров окна, доступности, кириллицы и закрытия; запуск без Python на чистой Windows; поведение без WebView2/.NET; реальная проверка офлайна и зависимостей распространения.
