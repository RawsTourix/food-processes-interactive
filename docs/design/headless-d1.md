# Headless-срез Д1: фактическая реализация

**Дата:** 28.10.2026. Код — `food_processes/`, проверки — `tests/test_headless.py`. Это исследовательский срез API, не полноценная лабораторная, модель теплообменника или психрометрия. R04 — открытая фиксированная учебная демонстрация из [эталонов](heat-exchanger-reference-cases.md); ни скрытых ответов заданий, ни системы их проверки в срезе нет.

## Работает

`Application.request` принимает конверт Д0 `api_version`, `request_id`, `op`, `args` и возвращает `outcome`, `data`, `diagnostics`. Тот же диспетчер вызывается CLI `python -m food_processes` для последовательности JSON Lines. Операции: `module.info`, `session.create`, `session.state`, `session.actions`, `session.command`, `material.get`, `session.save`, `storage.write`, `storage.read`, `session.restore`. Справка собственная, по ID `hx.fixture` и `air.region`.

Теплообменник: команды `set_conditions`, `save_draft`, `capture_snapshot`, `show_fixture`, `get_stand_readings`. Температуры вводятся в `degC` или абсолютных `K`, теплоёмкостные расходы и UA — `W/K` или `kW/K`; сохраняются исходные и нормализованные единицы. Температурное смещение применяется только к абсолютной температуре, а в `W/K` обозначает разность. `show_fixture` доступна исключительно для снимка с условиями R04: противоток, 80/20 °C, оба C и UA — 1000 W/K. Выход — 30000 W, 50/50 °C, явно помеченный `demonstration_fixture`, не расчёт или измерение. Изменение параметров не переписывает снимок. Запрос показаний стенда возвращает `model.stand_unavailable`.

Влажный воздух: `select_region` сохраняет точку с `representation: qualitative`, областями без физической интерпретации и ссылкой на `air.region`; сейчас поддерживается только `schematic-area-a`. `get_properties` и `construct_process` возвращают `model.psychrometrics_unavailable`. Величин, координат и численной модели нет.

Мутации требуют `expected_revision`; отказ, неизвестная команда и конфликт не меняют состояние. Сырые строковые черновики сохраняются отдельно, при ошибке ввода не теряются. В ответах и JSON запрещены нечисловые специальные значения. Документ версии 1 содержит модульные данные, снимки, исходные единицы и ревизию; при восстановлении его проверяет модуль. Восстановление в уже открытый сеанс с тем же ID отклоняется, чтобы не потерять текущее состояние.

`session.save` лишь формирует документ. `storage.write` выполняет запись временного файла в тот же каталог с `flush`/`fsync` и `os.replace`; `storage.read` возвращает проверенный документ, который затем принимает `session.restore`. JSON-запрос допускает только ASCII-имя файла `*.json` без пути; `--storage-dir` и `Application(storage_dir=...)` — доверенная настройка запуска. По умолчанию каталог находится в профиле пользователя, вне проекта и EXE. Проверка разрешённого имени и отклонение существующей символической ссылки не являются полной защитой от конкурентной подмены файлов в недоверенном общем каталоге: использовать личный каталог; атомарность при сбое питания и многопроцессный доступ дополнительно не проверены (Q16).

## Изменения и границы контракта Д0

- В Д0 предлагается `calculate_ideal` с `ideal_model`. В Д1 реализована `show_fixture` с типом `demonstration_fixture`: никакая формула ε–NTU не исполняется, число выдаётся только для R04. Это осознанное сужение, не изменение физической постановки.
- ID сеансов присваиваются последовательно в процессе (`s1`, `s2`); восстановление совпадающего открытого ID возвращает конфликт. ID предназначены для локального среза и не гарантируют уникальности между независимыми процессами.
- `session.results`, `session.export`, `answer.put`, `answer.check`, независимые общие типы результатов и автоматическая проверка ответов не реализованы. R04 — **открытая демонстрация**, а не скрытый эталон задачи. Контент справки не содержит численных ответов. Правила защиты настоящих скрытых ответов ещё не проверены.
- `session.actions` сообщает причины недоступности для модели и некоторых условий; дальнейшая полнота объявлений действий и политик доступности требует отдельной проверки. Сохранение и восстановление — JSON-документ с явными командами, автоматического сохранения и переноса отчёта нет.
- Д0 не определил политику имён файлов и коллизий ID. В Д1 выбрано ограничение простым именем и отказ коллизии; многопроцессная синхронизация, защищённость от гонок на уровне файловой системы, миграции и восстановление после аварии остаются открытыми.
