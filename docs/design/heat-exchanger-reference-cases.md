Для R09 отношение `Q̇/Q̇_max` и обычная LMTD неопределены; скрипт вычисляет формальное ε как предельную характеристику конструкции, но в таблице опытная эффективность обозначена прочерком. Независимое интегрирование RK4 половины длины с 600 шагами отличается максимум на 3,5·10⁻¹³ °C. Это вычисленная точка учебной модели, а не установленное положение датчика. Для воспроизведения использовать определения `closed` и `rk` из скрипта ниже, затем выполнить:

```python
for mode in ('parallel', 'counter'):
    _, _, _, cout = closed(mode, 1000, 2000, 1000, 80, 20)
    k = 1000 * (1/1000 + (1 if mode == 'parallel' else -1)/2000)
    cold0 = 20 if mode == 'parallel' else cout
    delta = 80 - cold0
    h = 80 - delta * 0.5 * (-math.expm1(-k * 0.5)/(k * 0.5))
    c = h - delta * math.exp(-k * 0.5)
    print(mode, h, c, 'RK4:', rk(mode, 1000, 2000, 500, 80, cold0, 600))
```

Предел `C_r→0` при NTU=1: `ε=1−exp(−1)=0,6321205588`; это аналитический предельный случай бесконечно большого второго C, не отдельный прогон с нулевым расходом. При NTU→∞ и C_r=0,5 прямоток стремится к 2/3, противоток — к 1. Отрицательные расходы, нулевое C, отрицательный UA и неверные свойства здесь не исполнялись: это требования к будущим проверкам входа, а не пройденные тесты.

## Независимая проверка

1. Основной путь: аналитическое ε–NTU с `expm1` и веткой равных C.
2. Второй путь: интегрирование 1D уравнений температуры RK4 по нормированной длине. Для прямотока известны оба входа слева; для противотока холодная температура слева определяется бисекцией из условия входа справа. Это независимый **численный метод решения тех же идеализированных уравнений**, не экспериментальная проверка.
3. Запущены сетки 300 и 600 шагов. Максимальное отличие аналитических выходов от RK4/600 среди напечатанных режимов — 4,12·10⁻¹¹ °C; максимальная разность RK4/300 и RK4/600 — 6,23·10⁻¹⁰ °C. Эти цифры — наблюдения данного скрипта, не гарантированные допуски для будущей реализации.
4. При положительных концевых разностях рассчитано `UA·LMTD`; проверена разность балансов горячего и холодного потоков. Максимальный напечатанный остаток баланса по выходам — 7,3·10⁻¹² Вт. Для R07 величина `UA·LMTD` отличается от Q̇ примерно на 8,6·10⁻⁷ Вт из-за вычитания почти равных температур: это иллюстрация ограничений float, а не измерительная погрешность.
5. Скрипт предполагает `T_h,in≥T_c,in`, положительные C и UA≥0; не является общим валидатором. Режимы с потерями, переменными свойствами, неравномерным распределением UA, реальными датчиками и переходным процессом им не проверены. Требуются отдельные эталоны и экспериментальные данные.

## Воспроизведение

Ниже приведён **исследовательский скрипт**, использованный для фактического прогона, включая точные входы и вычисление остатков. Его можно сохранить как временный `hx_reference.py` и выполнить `python hx_reference.py`; он не является модулем приложения и не добавляет зависимости.

```python
import math,json

def closed(mode,ch,cc,ua,th,tc):
 cm=min(ch,cc); cr=cm/max(ch,cc); n=ua/cm
 if ua==0: e=0.
 elif mode=='parallel':e=-math.expm1(-n*(1+cr))/(1+cr)
 elif cr==1:e=n/(1+n)
 else:
  v=-math.expm1(-n*(1-cr)); e=v/((1-cr)+cr*v)
 q=e*cm*(th-tc); return e,q,th-q/ch,tc+q/cc

def rk(mode,ch,cc,ua,h,c,n):
 def f(h,c):
  z=ua*(h-c);return -z/ch, (z/cc if mode=='parallel' else -z/cc)
 step=1/n
 for _ in range(n):
  a,b=f(h,c); d,e=f(h+step*a/2,c+step*b/2); g,j=f(h+step*d/2,c+step*e/2); k,l=f(h+step*g,c+step*j)
  h+=step*(a+2*d+2*g+k)/6;c+=step*(b+2*e+2*j+l)/6
 return h,c

def solution(mode,ch,cc,ua,th,tc,n):
 if th==tc or ua==0:return th,tc
 if mode=='parallel':return rk(mode,ch,cc,ua,th,tc,n)
 lo,hi=tc,th
 for _ in range(60):
  mid=(lo+hi)/2;_,right=rk(mode,ch,cc,ua,th,mid,n)
  if right>tc:hi=mid
  else:lo=mid
 cold=(lo+hi)/2; hot,_=rk(mode,ch,cc,ua,th,cold,n);return hot,cold

def lmtd(a,b):
 if a<=0 or b<=0:return None
 if abs(a-b)<1e-12:return (a+b)/2
 return (a-b)/math.log1p((a-b)/b)
cases=[('unequal-P','parallel',1000,2000,1000,80,20),('unequal-C','counter',1000,2000,1000,80,20),('equal-P','parallel',1000,1000,1000,80,20),('equal-C','counter',1000,1000,1000,80,20),('small-P','parallel',1000,2000,.001,80,20),('small-C','counter',1000,2000,.001,80,20),('large-P','parallel',1000,2000,10000,80,20),('large-C','counter',1000,2000,10000,80,20),('same-T','counter',1000,2000,1000,50,50),('zero-UA','counter',1000,2000,0,80,20),('near-equal','counter',1000,1000.000001,1000,80,20),('area-4x','counter',1000,2000,4000,80,20)]
for ident,mode,ch,cc,ua,th,tc in cases:
 e,q,ho,co=closed(mode,ch,cc,ua,th,tc); h300,c300=solution(mode,ch,cc,ua,th,tc,300);h600,c600=solution(mode,ch,cc,ua,th,tc,600)
 a=th-tc if mode=='parallel' else th-co;b=ho-co if mode=='parallel' else ho-tc; l=lmtd(a,b); ref=ua*l if l is not None else None
 print(json.dumps(dict(id=ident,ntu=ua/min(ch,cc),cr=min(ch,cc)/max(ch,cc),e=e,q=q,hot=ho,cold=co,rk600_hot=h600,rk600_cold=c600,rk300_600=max(abs(h300-h600),abs(c300-c600)),closed_rk=max(abs(ho-h600),abs(co-c600)),lmtd=l,lmtd_q=ref,balance=ch*(th-ho)-cc*(co-tc))))
```
