# Предварительное ТЗ — Food Processes Interactive

**Статус:** DRAFT / обсуждается. **Дата:** 27.10.2026.
**Источники:** требования пользователя и предварительный обзор архива ПиАПП. Этот файл НЕ подтверждает точность формул и НЕ заменяет первоисточники.

## 1. Назначение

Компактное русскоязычное офлайн-приложение Windows для самостоятельного выполнения виртуальных лабораторных работ по ПиАПП и обращения к связанным учебным материалам. Ориентир — понятность, достоверность, интерактивность, небольшая сборка и отсутствие лишних функций.

## 2. Разделы

1. **Лабораторные** — схема установки, знакомство с оборудованием, этапы опыта, настройка параметров, показания, расчёты, протокол и подсказки.
2. **Справочник** — определения, величины, формулы, единицы измерения, физические свойства, условия применения зависимостей.
3. **Материалы** — лекции, методические сведения, последовательности работ, связанные с первоисточниками.
4. **Экзамен** — краткие, проверенные памятки по большинству вопросов в рамках доступных тем; без обязательного генератора билетов и оценки устных ответов.
5. **Сохранение** — не отдельный экран, а фоновая функция: параметры, протоколы, режимы, прогресс. Экспорт/импорт для переноса и резервной копии.

Один материал хранится один раз и доступен по ID из нескольких разделов, включая контекстную справку лабораторной.

## 3. Основная лабораторная: теплообменник

Рассмотреть теплообменник «труба в трубе», прямоток и противоток, потоки воды и молока согласно оригинальной методике; последовательность включения оборудования, настройку расходов и температур, наблюдение показаний, заполнение протокола, расчёт критериев подобия и показателей теплообмена. Сначала требуется сопоставить все шаги с методическими указаниями и оригинальным приложением.

**Нельзя предполагать без проверки:** геометрию аппарата, алгоритм виртуальных датчиков, модель переходных процессов, все корреляции, границы Re, трактовку Kт/Kд, теплового КПД и некоторые обозначения из исторического пособия.

Другие лабораторные — по результатам предметного аудита; потенциальные кандидаты: влажный воздух, гидродинамика, фильтр-пресс, сушильная установка, центрифугирование, выпаривание, ректификация. Наличие материала не означает готовую физическую модель.

## 4. Учебный сценарий

Пользователь открывает лабораторную, знакомится с целью и устройством установки, задаёт/изменяет параметры, выполняет действия, считывает виртуальные показания, заносит их в протокол, выполняет расчёты, сверяет результаты и сохраняет работу. Помощь открывается в контексте выбранного элемента/формулы; материал тот же, что в общем справочнике.

Подсказки различают:
- **Ошибка:** действие или значение недопустимо; объяснить причину и конкретное поле.
- **Предупреждение:** действие возможно, но влияет на достоверность результата или нарушает рекомендованный порядок.
- **Методическая подсказка:** где взять величину, что означает параметр и какая формула применима.

Не подменять учебную самостоятельность автоматическими ответами без выбора пользователя. Не блокировать физически допустимые исследования только потому, что они не совпадают с учебным примером.

## 5. API-first и проверяемость

Обязателен независимый от GUI Python-пакет с:
- созданием / загрузкой лабораторного сеанса;
- чтением состояния установки, входных значений и результатов;
- выполнением типизированных команд (режим, ввод, насос, запись, расчёт);
- структурированными ошибками с кодом, полем, объяснением и ссылкой на методику;
- воспроизводимым временем модели там, где есть обоснованная динамика;
- сериализацией, восстановлением и версионированием сохранений;
- трассировкой расчётов (формула, значения, единицы, источник/допущение).

Для Codex предусмотреть CLI запуска сценариев из JSON и JSON-ответы; CLI и GUI должны обращаться к одному Python-ядру. Не вводить HTTP-сервер без необходимости.

**Критерий готовности ядра:** без окна программы выполнить типовой опыт, намеренно допустить несколько ошибок, получить корректные диагностические сообщения, исправить ввод, вычислить результаты, сохранить и восстановить сеанс. Повторение сценария даёт тот же результат.

## 6. Интерфейс

Первый ориентир: Python + pywebview (WebView2 для Windows), HTML/CSS/SVG и небольшой объём JavaScript. Интерфейс русскоязычный, современный и сдержанный; схема установки интерактивна. Единое состояние хранится в ядре, UI не дублирует физические формулы и не генерирует «показания» самостоятельно. Анимация служит пониманию процесса, не выдаётся за научную симуляцию при отсутствии соответствующей модели.

Нужны управление масштабом/размером окна, читаемые единицы, контекстная справка, сохранение вводов при закрытии/перезапуске. Поддержка клавиатуры и понятные состояния ошибок.

## 7. Данные и распространение

Выходной формат: один `.exe` для Windows x64 без установки Python и ручной установки библиотек Python. Зависимость от WebView2 Runtime и реальная переносимость должны быть проверены на чистой Windows; статус сборки нельзя объявить «полностью автономным» без такого теста.

**Ориентир размера:** желательно ≤40 МБ, проверить достижимость; не жертвовать корректностью и стабильностью ради цифры. Пользовательские данные хранятся отдельно от EXE (например, в LocalAppData), чтобы обновление программы не уничтожало сохранения. Для передачи и резервного копирования — отдельный экспорт.

## 8. Что не входит в первый релиз

Регистрация, облачная синхронизация, AI-преподаватель, микросервисы, 3D-движок, сложная аналитика обучения, обязательная серверная БД, автоматическая генерация экзаменационных билетов. Не добавлять их без нового решения.

## 9. Приёмка

- Учебный сценарий и результаты соотносятся с первоисточниками; спорные положения явно отмечены.
- Расчётное ядро тестируется без GUI; нет необъяснённых `NaN` или выдуманных величин.
- GUI вызывает те же команды, что CLI; введённые данные и промежуточные результаты не исчезают при закрытии отдельных окон.
- Ошибки и предупреждения содержательны и связаны с элементами интерфейса.
- Справка использует единый контент по идентификаторам.
- Все разделы и сообщения полностью русскоязычны.
- Упаковка и запуск проверены на Windows; размер и зависимость от WebView2 зафиксированы фактически.

## 10. Неопределённости перед окончательным ТЗ

Сверить состав реальных лабораторных и экзаменационных вопросов; исследовать оригинальный Flash EXE в изолированной среде; найти независимые числовые эталоны; утвердить математическую модель датчиков и ограничения; проверить упаковку pywebview в одиночный EXE; решить, какой объём учебных материалов разрешено включать в публичную сборку.

## 11. Источники, приватные файлы и локальный HTTP

- GitHub содержит собственный код, документацию, тесты и проверенные производные материалы, допустимые к распространению.
- Оригинальная Flash-программа и исходные методические указания хранятся локально на ноутбуке владельца, не в публичном репозитории.
- Codex, работающий с клоном GitHub в облаке, не получает доступ к ноутбуку автоматически. Аудит первоисточников выполняется в локальной среде Codex с предоставленными путями либо по отдельно переданным выдержкам/результатам исследования.
- По возможности держать закрытые материалы вне рабочего дерева репозитория. Для временных материалов внутри клона — игнорируемый каталог `local-sources/`; проверять подготовленные к коммиту файлы. Не публиковать выдержки/ресурсы без оценки прав.
- В pywebview встроенный локальный HTTP-сервер может использоваться **только для отдачи HTML/CSS/JS/SVG**, не для вычислений и не как публичный веб-сервис. При относительном локальном entrypoint он запускается автоматически. Отсутствие интернета не препятствует его работе.
- Взаимодействие с Python вести через встроенный мост `window.pywebview.api`; отдельный HTTP API, Flask или FastAPI по умолчанию не нужен.
- Реальные ограничения `file://`, упаковку статики в один EXE, прослушиваемый адрес локального сервера и недоступность пользовательских/приватных файлов через его корень проверить в техническом прототипе.
