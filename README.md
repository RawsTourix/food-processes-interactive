# Food Processes Interactive

Локальный интерактивный практикум по дисциплине «Процессы и аппараты пищевых производств» (ПиАПП).

**Статус: проектирование / ТЗ 0.3.** Статический и методический аудит оригинального Flash-приложения выполнен в необходимом для проектирования объёме. Нет утверждённой физической модели виртуальных показаний, реализации лабораторных или готового EXE.

## Цель

Создать компактное Windows-приложение с несколькими интерактивными лабораторными работами **и учебными инструментами разных типов**: виртуальными установками, диаграммами, графическими схемами и расчётными исследованиями. Пользователь изучает устройство установки, выполняет опыт, вводит параметры, проводит вычисления, получает понятные подсказки и сохраняет результаты.

Содержимое программы: **лабораторные · справочник · методические материалы · краткие памятки к экзамену · сохранение работы**.

Методическая информация хранится в одном месте и открывается по ссылкам как из лабораторных, так и из общих разделов.

## Техническое направление (предварительно)

- Python — моделирование, вычисления, проверка действий, сохранение и автоматические тесты.
- pywebview — оболочка настольного приложения.
- HTML/CSS/SVG/минимальный JavaScript — интерфейс и анимации.
- API-first: полный лабораторный сценарий должен выполняться без GUI (Python API и CLI).
- Windows x64, целевой формат поставки — один автономно запускаемый `.exe`, без установки Python; минимизация размера и проверка зависимости от WebView2.
- Офлайн-работа без аккаунтов и внешних сервисов.

Технологии уточняются после пробной сборки и измерений.

## Разработка и материалы

Начальная лабораторная — теплообменник (прямоток/противоток). Предварительный портфель охватывает восемь направлений; их научная и методическая готовность оценивается раздельно. Остальные лабораторные отбираются после аудита имеющихся методических указаний. Общая архитектура не должна требовать одинаковой формы работы от виртуального стенда и, например, i–d-диаграммы. Оригинальная Flash-программа используется как референс учебного сценария; её поведение и результаты подлежат проверке, а не слепому копированию.

Не размещать в публичном репозитории оригинальный EXE, сторонние PDF или графические ресурсы без подтверждения прав.

## Где лежат исходные материалы

**GitHub:** исходный код программы, собственная проектная документация, спецификации, тесты и проверенные производные учебные материалы, разрешённые к публикации.

**Только на ноутбуке владельца:** оригинальный Flash EXE, исходные методические указания (PDF, DOCX и др.) и материалы для их анализа. Кодексу эти файлы доступны **только в локальном рабочем окружении**, если ему явно предоставлен путь; клонирование репозитория само по себе их не предоставляет.

Исходники могут лежать **вне папки репозитория**. Если временно используются внутри рабочего дерева, класть их в игнорируемую `local-sources/` и проверять `git status` перед любым коммитом. `.gitignore` не защищает от принудительного добавления `git add -f`.

## Локальный HTTP в pywebview

Встроенный сервер pywebview может обслуживать **локальные файлы интерфейса** (HTML, CSS, JS, SVG) по HTTP на компьютере без доступа к интернету; он не заменяет Python API и не требует облачного сервера. При относительном пути к `index.html` pywebview обычно запускает такой сервер автоматически. Сам браузерный рендеринг не требует HTTP, но вариант `file://` имеет ограничения. Отдельный Flask/FastAPI не планируется.

При реализации: не размещать приватные методички/EXE в каталоге, обслуживаемом HTTP; исключить доступ извне (проверить привязку к loopback и поведение актуальной версии pywebview); не загружать удалённые CDN и ресурсы.
